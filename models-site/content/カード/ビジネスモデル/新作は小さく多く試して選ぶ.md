**原則**: 新作は 1 本ずつ作り込まず、小さな試作を数多く並行して作り、採用したものだけを本実装に移す。

## なぜ

- 自分で 1 本ずつ作るのではなく、ゲームを量産する仕組み（Idle Factory）を作り始めた（ADR-0035）
- HTML がテーマ・第一印象・放置での見やすさを最速で試せ、形を揃えると生成・レビュー・移植を扱いやすくなる（ADR-0038）

## 規則

| 規則 | 範囲 | 根拠 |
| --- | --- | --- |
| AI エージェントを役割ごとの組織（Theme PM → Director → Core Value PM / Monetization PM → Engineers）にし、月 1 万ドル以上稼ぐ放置ゲームを自律的に作らせる | Idle-Factory | ADR-0035 |
| 人がプレイテストして判断する Director Playtest Guide を置く | Idle-Factory | ADR-0035 |
| 試作は外部依存のない 1 枚の HTML で作り、採用したものだけを Unity ECS へ移植する | Idle-Factory | ADR-0038 |
| 新作の種は共通の C# ドメイン＋Blazor の試作場で、メンバーごとに小さく並行して試す | 共通ライブラリ | ADR-0017 |
| 共有パッケージを切り出し、製品ラインごとに独立して出荷する | 共通ライブラリ | ADR-0067 |

## 境界

- ADR-0035 の理由は文書に記載がない
- ADR-0017 の理由は記述がない
