**原則**: 施策を打つ前に、効果の段（露出→反応→送客→獲得→定着）を測れる置き場と道具を作る。数字の置き場は認証の裏に置く。

## なぜ

- 送客の段が抜けていると、見られなかったのか刺さらなかったのかを切り分けられない（ADR-0139）
- 「API キーなどは公開してはならず、画面上のデータもオープンにしていいものではない」（ユーザー、ADR-0040）
- 判断の根拠を後から確認できるようにするため（ADR-0030）

## 規則

| 規則 | 範囲 | 根拠 |
| --- | --- | --- |
| 販促の正本を置き、施策ごとに「出したもの→数字→学び」を残す。投稿前後 3 日を見る。根拠のない仮説は検証待ちの表に分ける | Idle-MInertia | ADR-0139 |
| 複数作品のプレイヤー行動指標は共通の Firebase にゲーム ID 別に集め、Blazor の集計ダッシュボードで見る | 共通ライブラリ | ADR-0024 |
| 販売分析ダッシュボードは API キーをサーバーに置かず、認証を通した人だけがデータを見られる形で公開する | Idle-MInertia | ADR-0040 |
| 確定申告は明細に費目・根拠・要確認メモの列を足して AI に仕分けさせ、複式簿記にして計算過程を MD に残す | 事業運営 | ADR-0030 |

## 境界

- モバイル版は収益より DL 数・コミュニティ・SNS フォロワーの拡大を KPI にする案（ADR-0098）は、採否が不明
- ADR-0024 の理由は記述がない

## 根拠となった決定

| No. | 日付 | 決定 |
| --- | --- | --- |
| ADR-0024 | 2025-09-22 | 複数作品のプレイヤー行動指標を、共通の Firebase プロジェクトにゲーム ID 別に集め、Blazor の集計ダッシュボードで見る |
| ADR-0030 | 2026-03-15 | 確定申告はカード明細とレシートを AI に費目と根拠つきで仕分けさせ、複式簿記に直して青色申告の控除枠に挑む |
| ADR-0040 | 2026-05-08 | 販売分析ダッシュボードはAPIキーをサーバーに置かず、認証を通した人だけがデータを見られる形で公開する |
| ADR-0098 | 2026-07-30 | Steam 版は誰が見ても別ゲームと分かる別タイトルとして自分単独で出し、モバイル版は共同事業として分配比率を保ったまま続ける（案） |
| ADR-0139 | 2026-08-31 | プレイヤー獲得のための販促は X 運営と分けて Idle MInertia 配下に記録し、次の施策より先に「露出→反応→送客→獲得→定着」を測れる状態にする |
