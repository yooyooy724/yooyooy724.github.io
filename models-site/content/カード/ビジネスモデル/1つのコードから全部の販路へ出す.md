**原則**: 同じ作品は 1 つのコードベースから、モバイル・Steam・Web ゲームサイトのすべてへ出す。版ごとに別のゲームを作らない。

## なぜ

- ADR の理由欄はどれも「不明」。「同じゲームを二重に保守しないため」と読まれている（ADR-0009）
- ルールを一か所に保ち、2 つの版を同じ内容で保守するためと読まれている（ADR-0004）
- モバイルで通る経路を同一に保ったまま PC を足すため（ADR-0089）

## 規則

| 規則 | 範囲 | 根拠 |
| --- | --- | --- |
| モバイル版はゲームのルール（Domain）を PC 版と共有し、画面だけ作り直して機能ごとに接続する | Idle-Spiral | ADR-0004 |
| Steam 版とモバイル版を同じコードベースから出し、版タグを m / s で分ける | Idle-Sphere | ADR-0009 |
| Web ゲームサイト（CrazyGames）向けは WebGL でビルドし、広告を CrazyGames SDK に差し替える | Idle-MInertia | ADR-0019 |
| Unity を待たず Web で回す作品は Blazor で作り直し、CrazyGames 向けにビルドする | Idle-Space-War | ADR-0016 |
| Steam 対応は境界インターフェースで抽象化し、ゲームロジックに `#if` を書き足さない | Idle-MInertia | ADR-0089 |
| 次のモバイル版も Steam のブランチから出し、本線への個別取り込みはしない | Idle-MInertia | ADR-0312 |

## 境界

- WebGL 版は試作にとどまる（ADR-0019）
- VR 版は保存・Steam・サーバーを切った軽い派生として試作した（ADR-0012）
- Idle Sphere では Steam 分岐を `#if` で入れていた。Idle MInertia から境界インターフェース方式に変えた（ADR-0089）

## 根拠となった決定

| No. | 日付 | 決定 |
| --- | --- | --- |
| ADR-0004 | 2023-01-22 | Idle Spiral のモバイル版は、ゲームのルール（Domain）を PC 版と共有し、画面だけ Doozy UI で作り直して機能ごとに「ドメイン接続」する |
| ADR-0009 | 2024-10-12 | Idle Sphere は Steam 版とモバイル版を同じコードベースから出し、版タグを m / s で分ける |
| ADR-0012 | 2025-01-25 | Idle Sphere の VR 版を、保存・Steam・サーバーを切った軽い派生として試作する |
| ADR-0016 | 2025-03-20 | 宇宙船の放置ゲーム（Idle Space War）は、Unity 版をやめて Blazor の Web 版として作り直し、CrazyGames 向けにビルドする |
| ADR-0019 | 2025-07-08 | Idle MInertia（当時の名前は Idle Gem）の WebGL 版を CrazyGames 向けに試作し、広告を CrazyGames SDK に差し替える |
| ADR-0089 | 2026-07-28 | Steam 対応は 6 つの境界インターフェースで全面抽象化し、ゲームロジックに `#if` を書き足さない |
| ADR-0312 | 2026-10-08 | 次のモバイル版も Steam のブランチから出す方向で、本線への個別取り込みはしない |
