**原則**: 開発中のものは、ストアのベータ機能や早期アクセスではなく、本番のビルドの中でテスターやキーを配った人だけに先に遊ばせる。消える範囲は先に約束する。

## なぜ

- 「自分でテスターかどうかを判定できるようにして、実際のリリースの中でテストする」（ユーザー、ADR-0074）
- ふつうの Steam キーは発売日まで遊べないため、Release State Override キーを使う（ADR-0319）
- 残タスクが多く、DLC と Cloud Save が実機で通っていない段階で出すため（ADR-0299）
- テスト期の進捗はテスト用データのため（ADR-0128）

## 規則

| 規則 | 範囲 | 根拠 |
| --- | --- | --- |
| 開発中のエリアはアプリ内のテスター判定で本番リリースに入れ、入れるのはテスターだけにする | Idle-MInertia | ADR-0074 |
| 告知では「消える進捗」と「残る報酬」を先に約束し、パッチノートに Testing Feature の節を設ける。参加は Discord の DM で申告制 | Idle-MInertia | ADR-0081 |
| 一般公開のとき、テスト期に積まれた進捗だけを一度だけ消す。テスター判定の配線は将来の限定公開用に残す | Idle-MInertia | ADR-0128 |
| Steam は早期アクセスで出さず、発売まで Release State Override キー（販売禁止）を配った人だけの限定公開にし、ストアページは「近日登場」のまま | Idle-MInertia | ADR-0319 |
| 限定公開中は DLC とクラウドセーブを見せず（実装は残す）、スタート画面に発売予定と不具合報告のお願いを大きめに出す | Idle-MInertia | ADR-0299, ADR-0320 |
| 試作中・未登録の DLC の見た目はリリースビルドに出さず、出さないことをテストで固定する | Idle-Sphere | ADR-0126 |
| 限定公開中の DLC 確認は、発売前フラグを触らず、エディタ限定の切り替えで「発売後の構成」にして行う | Idle-MInertia | ADR-0415 |

## 境界

- Area2 まではプラットフォームのテスト機能を使っていた。仕組みを変えた理由は不明（ADR-0074）
- 早期アクセスで出す案（ADR-0299）は翌日の ADR-0319 で撤回
- Steam 版は期限を設けず品質優先とした（ADR-0090）が、ADR-0319 では 11 月の発売予定を置いている
- 早期アクセスを優先するため、実績とヒントを後回しにした（ADR-0294）
- ADR-0081 の理由はコミットに記述がない

## 根拠となった決定

| No. | 日付 | 決定 |
