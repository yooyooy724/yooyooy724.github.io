**原則**: レイアウトとスタイルの責務は UXML と USS が持ち、View の C# は要素を名前で引いて ViewModel と繋ぐだけにする。状態で絵が変わるときは状態ごとの要素を UXML に並べる。本線で UI を変えたら横長用の UXML にも必ず反映する。

## なぜ

- C# で要素を作るとデザインの編集が困難になる。「二度としないように Skill に残しておいて」（ADR-0132、本人の指示）
- UI Builder は UXML に書かれた Style しか読まず、Editor での編集ができなくなる（ADR-0338）
- このプロジェクトは徹底的にきれいな設計をいかに保ち続けられるかが重要（ADR-0229、本人の発言）
- 「Minertia 側であった UI の変更は必ず H にも反映させるよう明記し、実行してください」（ADR-0185、本人の指示）

## 規則

| 規則 | 範囲 | 根拠 |

| UI Builder で付けた寸法・色はインラインから USS に移す | Idle-MInertia | ADR-0270 |
| 縦横で挙動や見た目が違うものは、共通テンプレートを書き換えず _H の UXML に分ける | Idle-MInertia | ADR-0326 |
| 縦横で構造を分けずに済む飾りは、列にクラスを付けて USS で出し分ける | Idle-MInertia | ADR-0311 |
| 本線（モバイル）で UI を変えたら横長用の UXML（_H）にも必ず反映する | Idle-MInertia | ADR-0185 |
| 位置は UXML、見た目は USS、コードには動き（距離・時間）だけを残す | Idle-MInertia | ADR-0407, ADR-0408 |
| 画面ごとに使う USS は、テーマではなくその UXML の Style で読み込む。全画面に効かせるもの（DLC の印）だけテーマから読む | Idle-MInertia | ADR-0190, ADR-0338 |
| 新しい USS を作ったら、参照する UXML を Reimport して Stylesheets に付いたことを確かめるまでを手順にする | Idle-MInertia | ADR-0283 |
| UXML の衝突は片側を機械的に選ばず 1 か所ずつ解決し、解決後に Template 宣言の欠落を検査する | Idle-MInertia | ADR-0217 |
| 色の変数（--name）は C# から書けないので、デザインごとの USS を生成してルートのクラスを付け替える | Idle-Factory | ADR-0214 |

## 境界

- ボタンの色はクラス指定が既定テーマに負けるため、既存の画面と同じく UXML のインラインで指定する（ADR-0339）
- USS のクラス切り替えで作った開閉（ADR-0232）は USS が画面に付かず取りやめ（ADR-0252）、ViewModel が状態を持ち UXML に状態別要素を置く形で作り直した（ADR-0262）
- SafeArea の要素ごと適用（ADR-0379）は右レールが崩れたため取り消した（ADR-0378）
