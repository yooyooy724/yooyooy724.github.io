**原則**: 端末の時計・メモリ・クライアントから届く値は改竄されうるものとして扱い、時刻はサーバーを優先し、鍵や秘密はクライアントにもリポジトリにも置かない。

## なぜ

- 改竄したスコアでランキングが壊れる（ADR-0011）
- 時計を戻すと何度でも報酬が取れ、記録が過去へ書き直される（ADR-0413）
- チーターによる極端な値のコンパニオンが続出した（ADR-0337）
- ハードコードされたキーから DLC を無料で取られる被害が出ている（ADR-0297、Steamworks 管理者の助言）
- 公開リポジトリにはブラウザの認証情報を置けず、所有者の検証を外すと第三者が書ける（ADR-0092）

## 規則

| 規則 | 範囲 | 根拠 |
| --- | --- | --- |
| 経過時間はサーバー時刻を優先し、記録を過去へは書き戻さない（今が記録より過去なら経過 0） | Idle-MInertia | ADR-0413 |
| 周期イベントの時刻取得は Func<DateTime> にしてテストできるようにする | Idle-MInertia | ADR-0028 |
| 端末の時計を変えると壊れる問題はシンプルな設計で直し、既存の被害者への対処は最小限にする | Idle-MInertia | ADR-0107 |
| メモリ改竄を検知したプレイヤーはランキングに参加させない | Idle-Sphere | ADR-0011 |
| 他プレイヤーに見せる値の上限は固定の境（30 と自分の到達レベルの大きいほう）で区切り、チーターだけを候補から外す | Idle-MInertia | ADR-0336, ADR-0337 |
| 実績の閾値は実データから決めるが、チーターの外れ値は外す | Idle-MInertia | ADR-0301 |
| Firestore のルールはキャッチオール許可を後から絞れないので、他人のビルドに書けない置き場（トップレベル）にする | Idle-MInertia | ADR-0048 |
| API キーは公開・サーバー設置せず、画面のデータも認証の後にだけ表示する | Idle-MInertia | ADR-0040 |
| Steam の Web API キーはリポジトリ・チャット・ノートに入れず、使うときは Cloud Functions の環境変数で関数の中だけで読む | Idle-MInertia | ADR-0297 |
| 鍵をクライアントへ返す Firebase 関数は置かない。秘密情報は追跡から外し、作り直しの手順書を置く | Idle-MInertia | ADR-0317 |
| 公開サイトへの書き込みはブラウザに認証を置かず、所有者の Issue だけを Actions でマージする | 全体 | ADR-0092 |
| 経歴などの非公開資料は公開リポジトリに置かず、非公開の保管庫で管理する | 全体 | ADR-0072 |

## 境界

- 「機内モードで時計を未来へ跳ばす」手口は許容する。オフライン報酬は課金通貨を直接得るものではなく、放置ゲーの「機内モードでも報酬が出る」体験を崩さない（ADR-0413）
- 就活ページの回答は本人が「誰も見ない」と判断し、公開リスクより利便を優先して public に置いた（ADR-0154）
- Idle Sphere の本番関数 getSteamApiKey はキーをクライアントへ返している。Idle MInertia では最初から逆の方針を守る（ADR-0297）

## 根拠となった決定

| No. | 日付 | 決定 |
| --- | --- | --- |
| ADR-0011 | 2024-11-24 | オンラインランキングを入れ、メモリ改竄を検知したプレイヤーは参加できなくする |
| ADR-0028 | 2026-02-22 | Nether を、決定論的な周期で開閉する期間イベントにする |
| ADR-0040 | 2026-05-08 | 販売分析ダッシュボードはAPIキーをサーバーに置かず、認証を通した人だけがデータを見られる形で公開する |
| ADR-0048 | 2026-06-09 | Nether に、他プレイヤーの装備ビルドを借りて一緒に潜る非同期の協力（コンパニオン）を入れる |
| ADR-0072 | 2026-07-08 | 就職活動の経歴資料を公開リポジトリから削除し、非公開の保管庫で管理する |
| ADR-0092 | 2026-07-28 | 設計ノートを GitHub Pages に公開し、別端末からの書き込みはブラウザに認証を置かず Issue → Actions でマージする |
| ADR-0107 | 2026-08-05 | 端末の時計を変えると壊れる問題は、シンプルな設計で直し、既存の被害者への対処は複数エージェントで精査して最小限にする |
| ADR-0297 | 2026-10-08 | Steam の Web API キーはリポジトリに入れず、使うときは Firebase の関数の環境変数に置く |
| ADR-0301 | 2026-10-08 | Steam 実績はオフラインで解除できないものも入れ、閾値は外れ値を除いた実データで決める |
| ADR-0317 | 2026-10-08 | 鍵をクライアントへ返す Firebase 関数は置かない |
| ADR-0336 | 2026-10-10 | コンパニオンの候補の上限は「30 と自分の到達レベルの大きいほう」。+3 の相対上限はやめる |
| ADR-0337 | 2026-10-10 | コンパニオンの候補は到達レベル +3 まで。maxLevel はサーバのトリガーが計算し、お気に入りの登録は +0 のまま |
| ADR-0413 | 2026-10-16 | オフライン報酬の時刻は、サーバー時刻を優先し、記録を過去へは戻さない |
