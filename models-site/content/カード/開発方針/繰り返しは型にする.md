**原則**: 繰り返す作業はスキル・指示書・スクリプトに固定し、繰り返した失敗は禁止事項や台帳として理由つきで書き込む。手順は人の記憶ではなく道具に持たせる。

## なぜ

- エージェントに毎回同じ前提と手順を守らせる（ADR-0034）
- 理由つきで残さないと同じ失敗を繰り返す（ADR-0145）
- 1 か月で消すと却下が黙って復活し、同じ行をもう一度却下する羽目になる（ADR-0161）
- どの AI・どのリポジトリからも同じ形で記録でき、2 台の PC の間でも揃う（ADR-0186、本人の判断）
- 同じ失敗が 2 回起き、原因の切り分けに時間がかかった（ADR-0283）

## 規則

| 規則 | 範囲 | 根拠 |
| --- | --- | --- |
| Claude Code と Codex 向けの指示書（CLAUDE.md / AGENTS.md）とスキルをリポジトリに置く | 全体 | ADR-0034 |
| スキルの使いどころは 1〜2 文で CLAUDE.md に書く | 全体 | ADR-0119 |
| 繰り返した禁止事項（View で new VisualElement()）はガイドライン Skill に残す | Idle-MInertia | ADR-0132 |
| 毎回同じ見た目にする作業（動画の倍速化・ラベル入れ）は固定値ごとスキル化し、失敗も理由つきで書き込む | 全体 | ADR-0145 |
| 却下した案は恒久の鍵を持つ台帳に残し、ゲートで止める | Idle-Factory | ADR-0161 |
| ADR の蓄積は MCP サーバー（adr_record・adr_git_digest）で行い、記録のたびに保管庫を commit・push する | 全体 | ADR-0186 |
| 道具の接続はプロジェクト別の直書きではなく、作業フォルダから決めるランチャー 1 つに一本化する | 全体 | ADR-0194, ADR-0195 |
| ビルドとストア提出は Deploy/<platform> の同じ型で自動化する | Idle-MInertia | ADR-0023 |
| 失敗して分かった手順（USS を作ったら UXML を Reimport）は作業の手順に含める | Idle-MInertia | ADR-0283 |
| 日次タスクは 1 日 1 枚の Markdown と /task スキルで管理する | 全体 | ADR-0137 |

## 境界

- /task は本人が叩いたときだけ動かし、フックや定期実行は入れない（ADR-0137）
- 機械的に判定できない規約を増やさない。ECS 前提の規約は ECS を使わないプロジェクトに適用しない（ADR-0153）
- 決まっていないことを決まったように書かない（ADR-0153）

## 根拠となった決定

| No. | 日付 | 決定 |
| --- | --- | --- |
| ADR-0023 | 2025-09-19 | ビルドとストア提出は Deploy/<platform> の同じ型で自動化し、Steam だけは fastlane に乗せず既定 dry-run のシェルにする |
| ADR-0034 | 2026-04-15 | Claude Code と Codex 向けの指示書（CLAUDE.md / AGENTS.md）とスキルをリポジトリに置いて開発させる |
| ADR-0119 | 2026-08-12 | grill-with-docs・prototype・diagnosing-bugs・wait-what を入れ、使いどころを1〜2文で CLAUDE.md に書く |
| ADR-0132 | 2026-08-25 | Viewで new VisualElement() を使うことを禁止し、二度と起きないようガイドラインSkillに書く |
| ADR-0137 | 2026-08-31 | プロジェクト横断の「その日やること」は YayuProjects/_tasks の1日1枚の Markdown と /task スキルで管理する |
| ADR-0145 | 2026-09-04 | X に出す画面収録の倍速化・ラベル入れ・音声差し替えは post-video スキルに固定し、毎回同じ見た目にする |
| ADR-0153 | 2026-09-10 | 全プロジェクト共通の実装規約のうち、ECS 前提の節は ECS を使わない Idle Sphere には適用しない |

| ADR-0186 | 2026-10-02 | ADR の蓄積は MCP サーバーで自動化する |
| ADR-0194 | 2026-10-02 | mcp-unity の接続先はプロジェクト別の設定を持たず、ランチャーが作業フォルダから決める形に一本化する |
| ADR-0195 | 2026-10-02 | mcp-unity は作業フォルダから組の Unity を選ぶ起動スクリプト経由で起動する |
| ADR-0283 | 2026-10-07 | 新しい USS を作ったら、参照する UXML を Unity で Reimport するところまでを手順にする |
