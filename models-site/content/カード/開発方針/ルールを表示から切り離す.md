**原則**: ゲームのルールは Unity に依存しない C# のドメインとして持ち、画面（Unity・Blazor・モバイル・PC）は境目でつなぎ直す。

## なぜ

- ドメインをテスト可能にし、保存方式や描画エンジンから独立させる（ADR-0008）
- Unity の起動やシーン作りを待たずに、ルールと数値を回して試せる（ADR-0015・ADR-0017）
- 同じルールを PC・モバイル・Web の版で二重に保守しない（ADR-0004・ADR-0009）
- チームは全員プログラマなので、コードを読めば仕様を理解・編集できる状態が最も保守しやすい（ADR-0083、本人の方針）

## 規則

| 規則 | 範囲 | 根拠 |
| --- | --- | --- |
| ドメインから永続化を排除し、Domain / Infrastructure / Application をアセンブリで分ける | 全体 | ADR-0008 |
| ドメインは Unity から独立したリポジトリ（GamesDomain）に置く | Idle-MInertia | ADR-0015 |
| Unity はドメインをソースではなくビルド済み DLL（Assets/Plugins）として取り込む | Idle-MInertia | ADR-0018 |
| 新作の種は共通の C# ドメイン＋Blazor の試作場で、画面なしで試す | 全体 | ADR-0015, ADR-0016, ADR-0017 |
| モデル層（会話システムも含む）は UnityEngine に依存させない | Idle-MInertia | ADR-0042 |
| MVVM を骨格にし、ViewModel は Pure C# 上の仮想 UI、Model はルールを表明する DDD のコードとする | Idle-MInertia | ADR-0083 |
| ドメインの外部依存は最小にし、Option / Fin だけの自前ライブラリに置き換える | Idle-MInertia | ADR-0021 |
| 古い依存（UniRx・UniTask・Zenject・R3）は API の機械的な置換ではなく、振る舞いの境界ごとに外す | Idle-Sphere | ADR-0116 |
| 共有パッケージ（com.idlesystem.*）はゲームと別のリポジトリに切り出し、各ゲームは共通基盤の上の薄いクライアントにする | 全体 | ADR-0067, ADR-0113 |
| 自作ライブラリ（Rakugaki）はソースを隠した DLL の埋め込みパッケージとして入れる | Rootflux | ADR-0167 |

## 境界

- Idle Spiral のモバイル版（ADR-0004）はこの原則の最初の形で、当時の理由は記録にない
- 仕様書は実装前の検討にだけ使う。実装後の正本はコード（ADR-0083。「正本は1か所」も参照）
- 技術都合だけでクラスを分けない（ADR-0083）

## 根拠となった決定

| No. | 日付 | 決定 |
| --- | --- | --- |
| ADR-0004 | 2023-01-22 | Idle Spiral のモバイル版は、ゲームのルール（Domain）を PC 版と共有し、画面だけ Doozy UI で作り直して機能ごとに「ドメイン接続」する |
| ADR-0008 | 2024-02-06 | ドメイン層から永続化を排除し、Domain / Infrastructure / Application をアセンブリで分ける |
| ADR-0015 | 2025-03-15 | ゲームのドメインを Unity から独立したリポジトリ（UpgradeDomain / GamesDomain）に移し、Blazor の画面で試作する |
| ADR-0016 | 2025-03-20 | 宇宙船の放置ゲーム（Idle Space War）は、Unity 版をやめて Blazor の Web 版として作り直し、CrazyGames 向けにビルドする |
| ADR-0017 | 2025-04-04 | 新作の種は、共通の C# ドメイン＋Blazor の試作場で、メンバーごとに小さく並行して試す |
| ADR-0018 | 2025-04-16 | Unity プロジェクトはドメインをソースではなくビルド済み DLL として取り込む |
| ADR-0021 | 2025-08-13 | ドメインから LanguageExt を外し、Option / Fin だけを持つ自前の IdleSystem.LanguageExt に置き換える |
| ADR-0042 | 2026-05-13 | キャラクターの会話システムを Phase 1〜8 に分けて作り、台詞は JSON マスタと専用の編集シーンで管理し、チュートリアルの進行で発火させる |
| ADR-0067 | 2026-07-04 | 共有の com.idlesystem.* パッケージを idle-system-core に切り出し、ゲームごとに独立して出荷する |
| ADR-0083 | 2026-07-24 | 仕様書は実装前の検討に使い、実装後は DDD で書いたドメインの C# コードを仕様の正本かつ全員プログラマのチームの共通言語にする |
| ADR-0113 | 2026-08-10 | Idle Sphere を多製品リポジトリから切り出し、共通の放置ゲーム基盤に乗る薄いクライアントにする |
| ADR-0116 | 2026-08-12 | UniRx・UniTask・Zenject・R3 は API の機械的な置換ではなく、振る舞いの境界ごとに外す |
| ADR-0167 | 2026-09-24 | 自作ライブラリ Rakugaki は、ソースを隠したDLLの埋め込みパッケージとしてゲームに入れる |
