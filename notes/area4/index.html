Area4 / マスタープレステージ 仕様

エンディング後に任意で行う、ゲーム全体の大きな周回。Area4 のボスコンテンツとセットで考え、Master 後に新しい通貨とバザーが開く。確定したことと、まだ案のことを分けて持つ。

1. 確定していること 確定

  • Area4 として出す。Area4 に Biome は無い（深さの軸が無い）
  • MasterPrestige コンテンツと、PvP 的なマルチプレイ要素を入れる
  • MasterPrestige はボスコンテンツとセット。最初のボスを倒すとエンディングロール（Thank you for playing）が流れ、その後に MasterPrestige が解放される
  • MasterPrestige は完全に任意 Discord 8/30 ya.yu
  • リセット対象外: Relic・装備スロットの Upgrade・ストレージの Upgrade・Diamond・Soul・BlueBox・Trade・INDEX・所持 Spell・Battle。ただし Battle の装備はリセット
  • Forge Level は残す。その代わり MaxLevel を徐々に上げる
  • MasterPrestige 後に新しい通貨 Geode（ジオード / 晶洞。内部 ID は Geode2）を追加する
  • 新しい通貨は洞窟の専用ブロックから、時間基準で出る。頻度は竿 1 本の釣りで Soul が出るのと同じ x1 で 0.5 個/日。倍率は通算ボス数 nで伸びる

2. 狙う体験

  1. ボスが近づく高揚
  2. 倒した後「今 Prestige するか、次のボスまで粘るか」を自分で決める
  3. Prestige 直後に再び軽快に伸びる
  4. 「損したかも」を一切混ぜない

棄却した案

「効果はそのまま、Level だけリセット」。Prestige が無料の割引になり、細かく回すほど得・Upgrade は後回しが最適・通貨の残りで後悔、と誘因が全部ボスと逆を向く。

MasterPrestige は「プレイヤーの負担が大きい」ものとして扱う。だから任意にする。ループが回るたびに全体が少しずつ強くなる、を長く続く形にする。 Discord 8/29–8/31

3. マスタープレステージ

解放の流れ 確定

Area4 の最初のボスを倒す→ エンディングロール「Thank you for playing」→ MasterPrestige 解放（押すかどうかは任意）→ 新しい通貨 x0 → x1、新しいバザーが開く

「全部 max したら」という条件（Poedel 案）は、最初のボス撃破に置き換える。

議論の経緯

Poedel: 全部 max した後の遊びとして。Forge Level は残して回数だけ戻す。ループのたびに強くなる。
ya.yu: エンディング後の任意コンテンツ。Forge Level は核なので賛成。Spell は残して同じものを取ったら Tier2。オートメーションの Upgrade は戻さない。
Poedel: ダイヤ Upgrade は上限を広げる（10/10 → 10/15）。Storage は Master ごとに 1 ページか 1 行増やす。
ya.yu: ダイヤの案は一歩先を行かれた。Storage の案も入れる。
ya.yu 9/17: リセット対象外を Diamond・Soul・BlueBox・Trade・INDEX・所持 Spell・Battle まで広げる（Battle の装備は戻す）。Master は最初のボス撃破 → エンディングロール → 解放。Forge Level は残し MaxLevel を徐々に上げる。Master 後に新しい通貨とバザー。

「損したかも」を出さない不変条件 案

  • Master で得るものは累計で単調増加。早く押しても遅く押しても、同じ到達点の総和は同じ
  • 残すものは一度も減らない（上の表の「残す」「残して伸びる」）
  • 押さない選択が常に安全。Master を要求するコンテンツは作らない

4. 新しい通貨とバザー

決まっていること 確定

  • MasterPrestige 後に新しい通貨を追加する
  • 演出は他の Prestige と同じ「通貨獲得の倍率」。ただし x1 始まりではなく x0 始まり（通貨X x0 → x1）。倍率が 0 の間は存在しないのと同じなので、解禁がなめらかに繋がる
  • 通貨は洞窟の中で出る。獲得数は Soul と同じ規模にしたいので、バランスは慎重に決める
  • 使い道は新しいバザー（Poedel のバザー案と同じ方向）
  • バザーには Forge Level 4 種の MaxLevel を 1 つ上げるアイテムが出る。これが「MaxLevel を徐々に上げる」の手段
Poedel のバザー案そのものは、この文書にまだ載っていない（Claude が把握していない）。共有してもらえればここへ足す。

取得の式 確定

  • 出どころ: 洞窟の専用ブロック。壊すと 1 個。Box ブロックの生成・破壊の口を流用する
  • 頻度は時間で決める。期待値 0.5 個/日 × x。掘る速さが上がっても頻度は変わらない
  • 基準は竿 1 本の釣りで Soul が出る頻度: 釣果あたり 0.0071% × 8.5 秒周期 × 水上率 0.7 ≈ 0.51 個/日（約 2 日に 1 個）
  • 実装: ブロックを壊すたびの出現確率 p = (0.5 × x ÷ 86400) ÷ 破壊速度(個/秒)。破壊速度は Box のオフライン予測で使っている PredictBreakBlockCountPerSec をそのまま使う
  • 倍率 x: エンディング前は x0（口を隠す）。最初のボス撃破で x1。以後は通算ボス数 n で x = 1 + 0.5 × (n − 1)。Master では戻さない（Master の回数では伸ばさない。急がせないため）
  • オフライン: 期待値は「時間 × 補正」で出す（補正は釣りの 0.7 と同じ考え方で実測して決める）。ただし個数は期待値を丸めずに確率で引く。期待値 λ に対して Poisson(λ) で個数を決める（平均は λ のまま、分散が実プレイと同じになる）
  • 確率で引く理由: 1 日おきに戻る人の期待値が 0.7 のとき、四捨五入だと毎回 0 個で永遠に手に入らない。確率なら 7 割の日に 1 個入る。また、実プレイの乱数によるばらつきをオフラインでも再現できる
通算ボス数 n倍率 x期待値 / 日1 個あたり
0x00出ない
1x1.00.5約 2 日
2x1.50.75約 1.3 日
3x2.01.0約 1 日
5x3.01.5約 16 時間

n あたり +0.5 は仮の値。バザーの値段（MaxLevel +1 の価格）と一緒に最終調整する。

通貨名 確定

  • 表示名は Geode（ja: ジオード / zh: 晶洞 / fr: Géode / ru: Жеода）
  • 内部 ID は Geode2。Geode は Box が使っているため（MultiCurrencyIdDef.BoxId）。ID を後から変えるとセーブ済みの残高が読めなくなるので固定する
  • クラス名は MasterCurrency* のまま。既存の Geode*（GeodeFactory / GeodeTypeConfig）は「盤面のブロック」を指すので衝突させない
要確認: notification.currency.geode（Box の通知での表示名）が既に「Geode / ジオード」になっている。通知では Box と新通貨が同じ名前で出るので、Box 側を「Box」に統一するか、新通貨の表記を変えるかを決める必要がある。

検討した候補 案

世界観（ベクトル論）から。既存の Soul は内部名 Onies＝「死んだベクトルの塊」なので、エンディング後の通貨はその対になる「生きた側」から取るのが筋がよい。

候補（英 / 日）由来x0 → x1 との相性所感
Will / イシ（意思）意思＝内部相が永遠に動き続ける「生きたベクトル」。評議会が「通貨にも燃料にも量産できない」と苛立つ唯一のもの。Soul（死んだベクトル）の対コアに触れた（＝最初のボスを倒した）後にだけ手に入る、という筋が通る推奨。テーマの核を通貨にする分、名前は短く
Flux / ゆらぎ失われた一本が抜けて格子が「永久の揺らぎ」に陥ったもの＝コアの意思「x0 で止まっていたものが動き出す」の演出そのもの次点。語感が軽く UI に収まりやすい
Phase / 相（そう）再帰ベクトルの内部相。同じ矢印でも中身が違う、を決めるもの倍率で増える「深さ」の表現に合う抽象的で、初見で何か分かりにくい
Lost Vector / 一本（いっぽん）コアから失われた一本の断片最終命題を名指しする重い。エンディング後の通貨としては直球すぎるかもしれない
Prime Shard / プライム片プライムコア（中心核の大宝石）の欠片ボス＝コアの一部、と読める宝石＝「止める側」なので、Master の意味（動き続ける）とは逆向き

選ぶときの軸: Soul（死んだ側）と対になるか / x0 → x1 の「動き出す」に合うか / 英語 UI で 1 語に収まるか。

5. Area4 の Prestige 確定

Area4 の中で回る、ボス討伐を軸にした Prestige。Master とは別の層。

項目内容
Level / コストリセットしない。upgradeCost = costCoef * totalLevel（通算）
解放ボス討伐で Prestige が解放される
報酬currencyRate の恒久倍率。倒したボス数が多いほど高い（粘る動機）
通貨持ち越し。いつ買っても同じ値段なので後悔が生まれない
上限upgradeLevelCap = 30 + 5 * defeatedBossCount（ボス 1 体につき +5）
順序ボス撃破 → 上限が開く → Prestige でレート上昇
敵 HPenemyHpBaseMult は攻撃倍率と切り離し、周回ごとに 3^(0.85 * 追加Level数) 程度
周期コストが線形なので k 周目の区間コストは線形に増える。25 日周期を保つなら rateMult(k) ≈ 1 + 0.3k の線形伸び。指数倍率は周期が崩壊する
初回6 日前後。4 周目あたりで 25 日に収束

7. PvP 的要素 案

非同期。Snapshot（凍結した ItemSet）を使い、負けても何も失わない。

案内容良い点懸念
1. マスターボス＝他人の SnapshotMaster した瞬間の ItemSet を凍結して上げる。他人の Area4 でマスターボスとして出現し、倒すと相手の m に応じた Master 点ボスの世代交代をプレイヤーが作るので新ボスの絵が要らない。既存の Snapshot を流用強すぎる Snapshot が壁 → m のリーグで出し分け
2. 防衛報酬自分のマスターボスが耐えた回数 / 時間で毎シーズン Master 点放置ゲームらしく、何もしなくても参加倒されても失うものは無い設計にする
3. 討伐ラダー今シーズンに倒したマスターボスの m の合計を RankingRoot のスコアに既存のシーズン・保留報酬を流用装備の強さ競争にしすぎない
4. 復讐マッチ自分のマスターボスを倒した相手が候補に出る高揚が最も強い通知の量。まずは 1〜3 で成立

不変条件

  • 負けても減るものが無い（通貨・Level・m・Snapshot のいずれも）
  • 攻撃側は「倒せた分だけ加点」、防衛側は「耐えた分だけ加点」。両方が正
  • マッチングは m のリーグで閉じる。Master を急いでもリーグが上がるだけ
  • マスターボスは凍結。相手が強化しても自分の盤面は変わらない
