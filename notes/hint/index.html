ヒント設計 — 画面ごとの要素

ヒントを実装する前の棚卸し。コンテンツごとに「画面」（区画）を分け、そこに並ぶ要素と、その説明を書き出した。Tutorial がどの区画で何を説明しているかも並べる。

更新 2026-10-08元: Unity の UXML・ローカライズ CSV・TutorialDomain.csノート一覧へ
Purpose

ヒントの単位は「区画」

  • 区画 = 1 つのコンテンツの中で、見え方がまとまっている場所。例: Equipment は 上部の装備を入れ替える画面＋下の 3 タブ = 4 区画
  • 各区画の表は「要素 / 説明 / Tutorial との関係」。説明は今の UI の文言とコードから書いた（文言の案ではない）
  • Tutorial の説明ポップアップは一度確認すると二度と開けない。ヒントはその読み直しを兼ねられる
  • 解禁前の区画にはヒントを出せない。区画ごとに解禁のタイミングを書いた（分からないものは「要確認」）

Prestige → Resurface（浮上） 名前は決定（10-08）

Prestige という名前を、このコンテンツの考え方が伝わる言葉に変えたい。考え方は「今の掘り進みと道具を手放して地上へ戻り、集めた宝石の力（ジェムパワー）で、次からの Soil / Tear の稼ぎを永く上げる」。Resurface（浮上）に決定。開発名 Prestige はコードと Localization Key に残す。

宝石の一覧の見出しは「奉納された宝石」（Offered Gems）に決定（実装済み）。「地下で掘る → 宝石を奉納する → 地上へ浮上する → 次の採掘が速くなる」という一つの流れで、Cave の「深度」ともつながる。

言い回しの方針

「ソイル浮上速度」のように、既存の文に「プレステージ」を機械的に「浮上」へ置き換えると意味がずれる。浮上は行為（地上へ戻ること）にだけ使い、浮上で得るものは既存の言葉で呼ぶ。

  1. 浮上 = 行為・出来事。「浮上する」「浮上すると」「前回の浮上」「浮上の自動化」「浮上のクールダウン」のように使う
  2. 浮上で得る倍率は「ソイル獲得倍率」「ティア獲得倍率」（Tutorial の既存の言葉）。「浮上倍率」「浮上ボーナス」のような新語は作らない
  3. 「〜速度」「〜倍率」の複合語に 浮上 を押し込まない。缶の効果（spp / tpp）は「浮上の速さ」ではなく「次回の獲得倍率が育つ速さ」なので、そう書く
  4. Soil / Tear の 2 種類は「ソイル浮上」「ティア浮上」（見出し・ボタン・自動化の名前だけ。文の中では「ソイルの浮上」）。Relic の名前は既存の「自動アップグレード：ソイル倍率」に合わせて「自動浮上：ソイル」
  5. 英語は Resurface（名詞・動詞）/ Resurfacing / Resurfaced。Tutorial の説明文は「地上へ戻る」「持ち帰る」の絵が立つように少し書き直す
  6. ついでに直す: クールタイム / クールダウンの混在 → クールダウン。英語で途切れている文（TearSoilPrestigeReset / TeaaUnlockKey）も直す
