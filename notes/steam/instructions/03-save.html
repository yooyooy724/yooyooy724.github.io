1. 目的

Steam 版で必要になるのは、PC をまたいだ復元とローカルファイルの改ざん耐性の2つ。 モバイル版は平文セーブのまま実ユーザーが遊んでおり、Steam 版だけの都合で形式を割ると 両版の互換が切れる。だから移行は両版共通の作業になる。

クラウドの正本は Firestore のまま変えない。Steam Cloud は複製先であり、 Steam の流儀（別 PC で自動復元）を成立させるためだけに使う。

2. 方針

優先順位

  1. 既存プレイヤーのセーブを壊さない。絶対条件。疑わしい変更は入れない
  2. 復旧できること。失敗したときに元へ戻せない処理を作らない
  3. 改ざん対策の強さ。最後。AES で防げない攻撃（メモリ改変・時計改ざん）は 受け入れた残存リスクであり、対策をこれ以上広げない

着手順

  1. 二重起動の防止。PC では同じセーブを2プロセスが書ける。破損原因の筆頭を先に塞ぐ
  2. 平文 → AES の移行
  3. Steam Cloud への複製と競合処理

移行の原則

  • 読みは両対応、書きは暗号化。平文が読めなくなる瞬間を作らない
  • 移行前のデータを消さない。移行に失敗しても元の平文から再開できること
  • 移行は起動時に自動で行い、プレイヤーに操作を求めない

クラウドの構成

  • Firestore が正本。Steam 版もモバイル版と同じ経路で Firestore へ保存する
  • Steam Cloud へは確定したセーブを複製するだけ。復元の第一候補は常に Firestore
  • Apple / Google / Steam の認証は独立させ、アカウント連携・セーブ統合を作らない
  • Firestore と Steam Cloud が食い違ったら、どちらを採るかはプレイヤーに選ばせる。 自動でどちらかを捨てない
  • NetherCompanion は Firestore REST のまま変えない

クラウドセーブの境界（指示書01）越しに実装する。 既存の CloudSave 実装は流用し、Steam 向けの複製と競合処理だけを足す。 資料と実コードが食い違ったら実コードが正。食い違いはコメントに残す。

3. あなたにお願いすること

次の確認は自動テストで代替できない。実施した結果をそのまま貼ってほしい。

#やること確かめること
1実際の平文セーブ（あなたの手元のプレイデータのコピー）で移行を走らせる進行が1項目も欠けずに引き継がれる
2PC を2台（または2環境）用意し、片方で進めてもう片方で起動するSteam Cloud 経由で復元される
3両方をオフラインで進めてから接続し、競合を起こす選択画面が出て、選んだ側が残る
4オフラインのまま起動 → プレイ → 終了 → 再起動するローカルだけで完結し、何も失われない
5ゲームを二重起動する2つ目が書き込めない（または起動しない）
1 は必ずコピーで行い、原本を残してください。 移行テストに使ったデータは、失敗した場合そのまま破損サンプルとして貼ってもらいます。

4. 完了の判断と、止まる条件

完了

  • 上の手動テスト5件がすべて通っている
  • 平文セーブの端末を更新しても、今までどおり遊べる（モバイル両OSで確認）
  • 移行後のファイルが平文で読めない
  • ドメインの変更分に単体テストがあり、通っている

手を止めて相談する

  • 移行ロジックが1件でもデータを落とすケースを見つけたとき
  • セーブデータの形式・スキーマ自体を変えないと成立しない、と判断したとき
  • Steam Cloud の容量・ファイル数制限に既存セーブが収まらないとき
  • 競合の選択画面で「どちらを選んでも何かが失われる」ケースが出たとき

戻し方

暗号化の書き込みはフラグで無効化できる形にしておき、問題が出たら書き込みだけを平文に戻す。 読みの両対応は残っているので、どの時点のセーブも読める状態が保たれる。
