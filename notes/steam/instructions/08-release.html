1. 目的

実装がどれだけ進んでも、ビルドが Steam に上がらなければリリースは存在しない。 しかも既存のデプロイ資産は旧作（Idle Sphere）向けのまま陳腐化しており、 プロジェクト設定にも旧作の識別子が残っている。配信経路は実質ゼロから作り直しになる。

AppID の新規取得には支払いと審査の待ち時間があり、スケジュール全体の起点になる。 実装の完成を待たずに手続きだけ先行させる。

2. 方針

優先順位

  1. 再現性。誰がやっても同じビルドが出る手順になっていること。属人化した1回きりの成功は成果ではない
  2. モバイルの出荷経路を壊さない。既存のビルドスクリプト・fastlane に手を入れない
  3. 速さ。アップロードは手動で確定。CI 化はしない

ビルド

  • Standalone 用のビルドスクリプトは新規に作る。旧作向けの既存デプロイスクリプトは直さず、使わない
  • プロジェクト設定に残る旧作の識別子（bundle ID・プロダクト名等）は、実 AppID 取得後に1回でまとめて直す
  • steam_appid.txt をリリース成果物に含めない（指示書02 の契約）
  • macOS は Universal Binary とし、署名と公証を通す。手順は必ず記録し、2回目から迷わない形にする
  • OS 別に Depot を分ける

ローカライズ

  • ゲーム内の対応言語（13言語）を維持する。Steam 対応で言語を減らさない
  • ストアページは7言語で用意する。文言はあなたの確認を通してから登録する

QA

  • チェックリストを先に作り、consuming しながら進める。終盤にまとめて消化しない
  • PC 固有の観点を落とさない: 解像度・DPI スケール・ウィンドウリサイズ・オフライン起動・ 長時間放置・二重起動・セーブ移行・オーバーレイ
  • Windows と macOS を同時に確認する。片方だけ通して「たぶん同じ」で済ませない

3. あなたにお願いすること

A. 手続き（代行できないもの）

#内容補足
1Steam Direct で新規 AppID を取得する（$100 の支払いを含む）スケジュールの起点。着手日だけ先に決めてほしい
2Apple Developer の証明書を用意する（macOS の署名・公証用）既存のモバイル用アカウントが使えるかの確認から
3Steamworks 管理画面の設定（Depot・ストアページ・価格・審査提出）入力する値の一覧はエージェントが用意する
4ストア素材の用意（スクリーンショット・カプセル画像・説明文の確定）文案・下書きはエージェントが出せる。最終確定はあなた

B. 実行して、結果を貼ってほしいもの

#やること貼ってほしいもの
1ビルドスクリプトで Windows / macOS のビルドを作る成否と、成果物のファイル構成
2macOS の署名・公証を通すコマンドの出力全文。失敗したらエラー全文
3steamcmd でアップロードする出力全文
4Steam クライアントからインストールして起動する（両OS）起動の成否と気づいたこと
5QA チェックリストを消化する各項目の結果。NG は再現手順つきで
1回で通ることを期待しない。 特に macOS の公証と steamcmd は初回で必ず何か起きる。 エラー全文を貼ってもらえれば、次の一手をこちらで出す。

4. 完了の判断と、止まる条件

完了

  • Windows / macOS のビルドが Steam に上がり、Steam クライアント経由で起動できる
  • ビルドからアップロードまでの手順が記録されており、2回目を別の人が再現できる
  • QA チェックリストが全件消化され、NG が残っていない（残す場合はあなたが明示的に容認したものだけ）
  • ストアページが7言語で埋まり、審査に提出できる状態になっている
  • モバイルのビルド経路に差分がない

手を止めて相談する

  • 審査で差し戻しが来たとき（対応方針はあなたの判断）
  • 公証・署名がどうしても通らず、macOS の 1.0 同時リリースが危ぶまれるとき
  • QA で見つかった NG が他の指示書の範囲（セーブ・レイアウト等）に波及するとき

リリース後の戻し方

Steam はビルドをブランチで切り替えられる。公開前の1つ前のビルドを常に残しておき、 重大な問題が出たら差し戻す。差し戻しの操作はあなたの管理画面から行うため、手順を渡しておく。
