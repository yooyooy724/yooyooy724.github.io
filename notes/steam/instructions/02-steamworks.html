1. 目的

ゲームロジックはビルド済み DLL として Unity に持ち込まれている。モバイルで動くことは分かっているが、 Standalone で動くかは一度も確かめていない。Standalone はスクリプトバックエンドも API プロファイルもモバイルと違う。

ここが動かない場合、移植計画そのものの見直しになる。仕様が固まるのを待たず、最初に確かめる。

Steamworks SDK の整理と初期化は従属的な作業である。 Steam を絡めた状態で失敗すると「DLL のせいか Steam のせいか」が分からなくなるため、先に足場を綺麗にする。

2. 進め方

1ラウンド1依頼

  • エージェントは依頼を1つだけ出して止まる。複数まとめて渡さない
  • あなたは実行し、結果をそのまま貼る。要約しない。エラーは全文
  • 結果を見てから次の依頼を出す。結果が返る前に次へ進まない
  • 手を動かす前に、いま何のためにそれを実行するのかを1行で示す
結果は加工せずに貼ってください。 「たぶん動いた」「エラーは無かったと思う」では切り分けができません。 画面のテキスト、ログの該当部分、Console の中身をそのまま貼るのが最短です。

ラウンドの並び

まとめて進めると、失敗したときに原因を特定できない。切り分けられる順に進める。

#確かめることエージェントあなた
1 Windows で DLL が動くか（Steam を一切絡めない） 検証用の最小構成と、実行手順を1つ出す Windows で実行し、結果を貼る
2 macOS で DLL が動くか 同じ検証を macOS 向けに出す macOS で実行し、結果を貼る
3 Steamworks SDK の重複解消 削除してよいものを、根拠つきで示す 削除し、Unity を再起動して Console を貼る
4 Scripting Define の整理 変更前後の値を差分で示す Editor を終了して変更し、Android と iOS のビルドを通して結果を貼る
5 Steam 初期化と、失敗時に落ちないこと 初期化処理を入れる Steam 起動時 / 未起動時の両方で実行し、ログを貼る

1 で結論が出た時点で、主目的は達成である。 NG が出たら 2 以降へ進まず、止まる条件 へ移る。

慎重さの配分

対象慎重さ理由
検証用のシーン・スクリプト・ビルド設定低い使い捨てでよい。汚くても速く答えが出る方が価値がある
Steamworks SDK の重複解消中どれが効いているか不明なまま消すと、原因が分からなくなる
Scripting Define の変更高いモバイルの出荷経路に直結する

守る契約

  • Steamworks 名前空間を、SDK を直接触る1ファイルの外へ出さない
  • steam_appid.txt をリリースビルドの成果物に含めない。開発時のみ実行ファイルの隣に置く
  • 既存の .cs・シーン構成・起動経路を変えない。検証は本編の起動経路の外で行う
  • ドメイン（NewCubeUpgradeDomain/）は変更しない

3. あなたにお願いすること

A. 最初に一度だけ答えてほしいこと

ここが分からないと、ラウンドの組み方そのものが決まらない。

質問なぜ必要か
macOS の実機を触れるか。触れるなら機種と OS バージョン触れない場合、macOS 対応を 1.0 に含め続けるかの判断が先に必要になる
Android のビルドを普段どう流しているか（既存のビルドスクリプト経由か、Editor から手動か）Define 変更後の確認を、あなたの普段の経路で行うため
iOS のビルドを通せる環境が今あるか（Xcode・証明書）通せないなら、Define 変更の安全確認が片肺になる。その前提で進め方を変える
Steam クライアントを入れている PC はどれか初期化の成功パターンを確認できる機械を決めるため

B. 実行して、結果を貼ってほしいもの

#やること貼ってほしいもの
1Windows の検証ビルドを実行して起動する画面に出たテキスト全部。出なければ Player.log の該当部分
2macOS の検証ビルドを実行して起動する同上。起動しない場合、その旨と OS が出したダイアログの文面
3Steamworks の重複を削除し、Unity を再起動するConsole を Clear してから再インポートし、出たエラーと警告の全文（0件なら「0件」）
4Unity Editor を完全に終了してから Define を変更し、Editor を起動するgit diff ProjectSettings/ProjectSettings.asset の出力
5Android のビルドを通す成否。失敗ならエラー全文
6iOS のビルドを通す成否。失敗ならエラー全文
7Steam クライアントを起動した状態でゲームを実行する初期化まわりのログ1行
8Steam クライアントを終了した状態でゲームを実行する同上。ゲームが起動し続けたかどうか
4 で Editor を開いたまま設定ファイルを編集しない。 Editor が終了時にメモリ上の値を書き戻すため、変更が巻き戻ります。 テキスト編集するなら Unity を完全に終了してから。Player Settings 画面から入力しても構いません。
5 と 6 を「たぶん大丈夫」で飛ばさない。 モバイル版はリリース済みで実ユーザーがプレイ中です。 Define の除去自体は無害なはずですが、出荷経路を実測なしで通さないでください。

C. あなたにしかできない手続きと判断

内容お願いしたいこと
AppID の新規取得（3217600 は旧作用） Steam Direct の支払いと審査が要り、代行できません。検証はテスト用 AppID で進められるので作業は止まりませんが、いつ着手するかだけ教えてください。ストア公開までの日程がここに載ります
DLL が動かなかった場合の方針 移植計画を見直すか、ドメイン側の変更まで踏み込むかの判断。結果が出た時点で相談します
macOS を 1.0 に含め続けるか 実機が用意できない場合のみ。A の回答次第で相談します

4. 完了の判断と、止まる条件

完了

  • Windows と macOS の両方で、ドメイン DLL がロードできるかの答えが出ている。 動く／動かないのどちらでも、答えが出ていれば主目的は達成
  • Steam クライアント未起動でもゲームが普通に起動する
  • Android と iOS のビルドが通る
  • Steamworks SDK の参照が1系統に絞られている
  • DLL を更新したあと、同じ検証をもう一度回せる
macOS を「たぶん同じ」で済ませない。 Windows で通っても macOS で落ちることがある。独立した関門として扱う。

手を止めて共有する

  • DLL がロードできなかったとき。回避策を試す前に、結果をそのまま共有する
  • 切り分けがドメイン側の変更（ターゲットフレームワークの変更など）に及ぶと分かったとき。 モバイル版が使う DLL も同時に変わる
  • Define を戻してもモバイルビルドが直らないとき

戻し方

Define の変更は単独で戻せる形にしておく。モバイルが壊れたときは、調査より先に戻す。 検証用の追加物は、問題が出なければ残してよい。
