繰り返しは型にする

繰り返しは型にする

2026年10月16日5 min read

  • 全体
  • 自動化
  • エージェントとの分担
✎ このページを編集

原則: 繰り返す作業はスキル・指示書・スクリプトに固定し、繰り返した失敗は禁止事項や台帳として理由つきで書き込む。手順は人の記憶ではなく道具に持たせる。

なぜ

  • エージェントに毎回同じ前提と手順を守らせる（ADR-0034）
  • 理由つきで残さないと同じ失敗を繰り返す（ADR-0145）
  • 1 か月で消すと却下が黙って復活し、同じ行をもう一度却下する羽目になる（ADR-0161）
  • どの AI・どのリポジトリからも同じ形で記録でき、2 台の PC の間でも揃う（ADR-0186、本人の判断）
  • 同じ失敗が 2 回起き、原因の切り分けに時間がかかった（ADR-0283）

規則

規則範囲根拠
Claude Code と Codex 向けの指示書（CLAUDE.md / AGENTS.md）とスキルをリポジトリに置く全体ADR-0034
スキルの使いどころは 1〜2 文で CLAUDE.md に書く全体ADR-0119
繰り返した禁止事項（View で new VisualElement()）はガイドライン Skill に残すIdle-MInertiaADR-0132
毎回同じ見た目にする作業（動画の倍速化・ラベル入れ）は固定値ごとスキル化し、失敗も理由つきで書き込む全体ADR-0145
却下した案は恒久の鍵を持つ台帳に残し、ゲートで止めるIdle-FactoryADR-0161
ADR の蓄積は MCP サーバー（adr_record・adr_git_digest）で行い、記録のたびに保管庫を commit・push する全体ADR-0186
道具の接続はプロジェクト別の直書きではなく、作業フォルダから決めるランチャー 1 つに一本化する全体ADR-0194, ADR-0195
ビルドとストア提出は Deploy/ の同じ型で自動化するIdle-MInertiaADR-0023
失敗して分かった手順（USS を作ったら UXML を Reimport）は作業の手順に含めるIdle-MInertiaADR-0283
日次タスクは 1 日 1 枚の Markdown と /task スキルで管理する全体ADR-0137

境界

  • /task は本人が叩いたときだけ動かし、フックや定期実行は入れない（ADR-0137）
  • 機械的に判定できない規約を増やさない。ECS 前提の規約は ECS を使わないプロジェクトに適用しない（ADR-0153）
  • 決まっていないことを決まったように書かない（ADR-0153）
